회수통 차감 계산 수정 업데이트

핵심 규칙
1. 회수통 기본단가가 3,000원인 거래처
   - 회수통 1개 반환 시 판매금액에서 3,000원 차감
   - 판매 반영단가: -3,000원
   - 예: 회수통 2개 -> -6,000원

2. 회수통 단가 설정이 없는 거래처
   - 보증금을 받지 않는 거래처로 처리
   - 판매 반영단가: 0원
   - 회수통 수량이 있어도 매출에서 차감하지 않음

3. 주문별 회수통단가가 따로 입력된 경우
   - 해당 주문의 입력단가를 우선 사용
   - 예: 예외단가 3,500원 -> 판매 반영단가 -3,500원

기존 데이터 자동 보정
- 이전 버전에서 회수통 +3,000원으로 저장된 판매자료는 서버 시작 시 -3,000원으로 자동 변경
- 기존 +3,500원은 -3,500원으로 변경
- 단가가 null이고 거래처 회수통 단가도 없으면 0원 처리
- 이미 음수 또는 0원인 자료는 건드리지 않음
- 데이터베이스 테이블 구조 변경 없음

명세서 생성 보정
- 생성되는 명세서에서 기존 template.xlsx의 잘못된 회수통 수식을 그대로 믿지 않음
- 해당 날짜 DB에 저장된 실제 회수통 금액을 사용해 합계 수식을 보정
- 예:
  기존 잘못된 수식: ...-F33*5500
  실제 회수통: 2개 × -3,000원
  생성 결과: 기존 회수통 항 제거 후 -6,000원 반영
- 회수통 단가가 없는 거래처는 기존 템플릿에 -3000 수식이 있더라도 제거

단가 관리 화면
- 회수통 단가 설정 자체는 기존처럼 3,000원(양수)로 입력
- 실제 판매금액에서만 자동으로 -3,000원 처리
- 설정이 없으면 0원

판매 수정 화면
- 회수통 판매 반영단가는 -3,000원처럼 표시
- 회수통을 직접 3,500원으로 입력해도 저장할 때 -3,500원으로 변환

적용 방법
1. 현재 실행 중인 서버에서 Ctrl + C
2. 압축을 풀고 src 폴더를 아래 프로젝트에 덮어쓰기
   F:\bean_sprout\salesmgmt
3. 다시 실행
   cd F:\bean_sprout\salesmgmt
   .\gradlew.bat clean bootRun
4. 서버 시작 시 기존 회수통 자료가 자동 보정됨
5. http://localhost:8080/sales 에서 회수통 단가와 금액 확인
6. http://localhost:8080/reports/monthly 에서 월매출 확인
7. http://localhost:8080/profit 에서 예상이익 확인
8. 명세서를 다시 생성해서 회수통 차감 확인

정상 예시
일반콩나물 10개 × 11,000원 = 110,000원
회수통 2개 × -3,000원 = -6,000원
합계 = 104,000원

회수통 단가가 없는 거래처
일반콩나물 10개 × 11,000원 = 110,000원
회수통 2개 × 0원 = 0원
합계 = 110,000원

- MySQL 비밀번호 변경 없음
- DB 스키마 변경 없음
