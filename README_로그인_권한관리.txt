로그인 + 관리자/아빠 계정 권한 업데이트

새 기능
1. Spring Security 로그인
2. 최초 관리자 계정 설정
3. 사용자 계정 관리
4. 관리자/업무용 권한 분리
5. 비밀번호 해시 저장
6. 로그아웃
7. 권한 없는 화면 차단
8. 기존 문자명세서 AJAX의 CSRF 처리

============================================================
중요: 이번 패치는 src만 덮어쓰면 안 됩니다.
============================================================

압축 안의:
- build.gradle
- src 폴더

둘 다 프로젝트에 덮어써야 합니다.

프로젝트:
F:\bean_sprout\salesmgmt

============================================================
1. 적용
============================================================

서버 종료:
Ctrl + C

압축 해제 후:
build.gradle -> F:\bean_sprout\salesmgmt\build.gradle
src          -> F:\bean_sprout\salesmgmt\src

그 다음:

cd F:\bean_sprout\salesmgmt
.\gradlew.bat --stop
.\gradlew.bat clean bootRun

처음에는 Spring Security 의존성을 새로 받기 때문에
평소보다 실행이 조금 더 걸릴 수 있습니다.

============================================================
2. 최초 관리자 계정 만들기
============================================================

반드시 서버가 실행되는 PC에서:

http://localhost:8080

접속.

사용자가 한 명도 없으면 로그인 화면 아래에:

"처음 사용하시나요? 관리자 계정 만들기"

링크가 표시됩니다.

누른 후:
- 관리자 아이디
- 표시 이름
- 비밀번호
- 비밀번호 확인

입력.

비밀번호 최소 8자.

초기 관리자 설정 /setup 은
보안을 위해 localhost에서만 가능합니다.

============================================================
3. 아빠 계정 만들기
============================================================

관리자 로그인 후 대시보드:

사용자 계정관리

또는:

http://localhost:8080/admin/users

새 계정:
아이디: 예) father
표시 이름: 예) 아버지
권한: 업무용
비밀번호: 원하는 비밀번호 8자 이상

생성.

============================================================
4. 권한
============================================================

관리자:
- 모든 기능

업무용(아빠):
- 대시보드
- 판매내역
- 일별 매출 캘린더
- 월 매출
- 명세서
- PDF/PNG 명세서
- 문자 명세서
- 재고
- 이익
- 입금/미수금
- 거래처/배송코스
- 네이버 경로 등 사용 가능

관리자 전용:
- 장부 업로드
- 새 월 장부 생성
- 기본 단가관리
- 행사/임시단가 관리
- DB 백업/복구
- 월 마감/마감해제
- 사용자 계정관리

아빠 계정으로 관리자 URL을 직접 입력해도 차단됩니다.

============================================================
5. 비밀번호
============================================================

app_users 테이블에 password_hash 형태로 저장됩니다.
평문 비밀번호는 DB에 저장하지 않습니다.

관리자는 /admin/users 에서
다른 계정의 비밀번호를 새 비밀번호로 재설정할 수 있습니다.

기존 비밀번호를 조회하는 기능은 없습니다.

============================================================
6. DB
============================================================

새 테이블:
app_users

ddl-auto:update가 켜져 있으므로 자동 생성됩니다.

기존 판매/거래처/재고/입금 DB 데이터에는 영향 없습니다.

전체 DB 백업 기능을 쓰면 app_users도 백업에 포함됩니다.

============================================================
7. Railway 배포할 때
============================================================

Railway에 올리기 전에 현재 로컬에서:
- 관리자 계정
- 아빠 계정

둘 다 먼저 만들어두는 것을 추천합니다.

그 후 MySQL 데이터를 Railway DB로 이전하면
계정의 해시 비밀번호도 같이 옮겨집니다.

그러면 배포 서버에서 /setup 을 다시 열 필요가 없습니다.
